BCCMusic — Future Feature Suggestions

This document outlines potential improvements and new features for the BCCMusic application, organized by category and priority.

1. Music File Uploads & Storage

This is the most impactful addition for preservation and daily use. Users scan scores, create parts in ScanScore/Dorico, and need a place to store those files alongside the score metadata.

What to Store

  • Original scans (PDF, PNG, JPG, TIFF)
  • Editable music files (Dorico .dorico, MusicXML .musicxml/.mxl, ScanScore projects)
  • Final printed parts (PDF exports from Dorico)
  • Full score conductor's copy (PDF)

Storage Options

Option Pros Cons Cost
Azure Blob Storage Native to Azure hosting, SDK support for Java/Spring, lifecycle policies, CDN integration Vendor lock-in to Azure ~$0.02/GB/month (hot tier)
AWS S3 Industry standard, excellent Java SDK, presigned URLs, versioning, lifecycle rules Extra if you're already on Azure ~$0.023/GB/month (standard)
Local/NAS file system No cloud dependency, full control, no recurring cost No redundancy unless mirrored, backup responsibility is yours, not accessible from outside Hardware cost only
Database BLOBs (MSSQL) Single system, transactional consistency Bloats database, terrible performance for large files, backup size explodes Included in DB cost but expensive at scale
Recommendation: Use Azure Blob Storage or AWS S3 for the actual files, and store only metadata (filename, size, content type, storage key/URL, upload date, uploaded by) in your MSSQL database. This keeps your database lean and your files accessible via signed URLs.

Suggested Database Schema

CREATE TABLE ScoreFiles (
    file_id         BIGINT IDENTITY PRIMARY KEY,
    score_id        BIGINT NOT NULL REFERENCES Scores(score_id),
    file_name       NVARCHAR(255) NOT NULL,
    file_type       VARCHAR(50) NOT NULL,       -- 'SCAN', 'PART_PDF', 'FULL_SCORE', 'EDITABLE', 'OTHER'
    content_type    VARCHAR(100) NOT NULL,       -- MIME type: 'application/pdf', 'image/png', etc.
    file_size_bytes BIGINT,
    storage_key     NVARCHAR(500) NOT NULL,      -- S3/Blob path or key
    part_id         BIGINT NULL REFERENCES Parts(part_id),  -- optional: link to specific part
    description     NVARCHAR(500),
    uploaded_by     BIGINT NOT NULL REFERENCES Account(account_id),
    uploaded_at     DATETIME2(0) NOT NULL DEFAULT GETDATE(),
    CONSTRAINT FK_ScoreFiles_Score FOREIGN KEY (score_id) REFERENCES Scores(score_id)
);

Implementation Approach

  1. Backend: Add a POST /scores/{scoreId}/files endpoint accepting multipart uploads
  2. Backend: Stream the file to blob storage, save metadata to DB, return the file record
  3. Backend: Add GET /scores/{scoreId}/files to list files, GET /scores/{scoreId}/files/{fileId}/download to generate a signed download URL
  4. Frontend: Add a "Files" section to ViewEditScore (collapsible like Parts/Comments)
  5. Frontend: Drag-and-drop upload area with progress indicator
  6. Frontend: File list showing name, type badge, size, uploader, and download button

File Organization Strategy

Store files with a path structure like:

scores/{scoreId}/{fileType}/{filename}
Example: scores/1042/scans/trumpet-1-page1.pdf
         scores/1042/parts/clarinet-2.pdf
         scores/1042/editable/full-score.dorico

2. Search & Discovery Enhancements

  • [HIGH] Full-text search across comments, part instruments, and composer names (not just title/tag)
  • [MED] Advanced filter panel: grade range slider, arrangement type checkboxes, purchased date range
  • [MED] "Recently viewed" or "Recently edited" section on Dashboard
  • [LOW] Saved searches / bookmarked filters
  • [LOW] Sort options: by date added, grade, title, last updated

3. Collaboration Improvements

  • [HIGH] Expand canEdit logic so collaborators can edit scores (currently only owner can)
  • [MED] Activity feed on Dashboard: "John added a comment to March Triumphant"
  • [MED] Email notifications when a collaborator edits your score
  • [LOW] Collaboration audit log (who changed what field, when)
  • [LOW] Per-score permission overrides (some collaborators can only edit specific scores)

4. Music Library Features

  • [HIGH] File uploads (see section 1 above)
  • [MED] Set lists / concert programs: group scores for a performance with ordering
  • [MED] "Needed parts" checklist for performance prep (which parts do we have? which are missing?)
  • [MED] Duplicate/clone a score (useful for alternate arrangements of the same piece)
  • [LOW] Bulk import from CSV or spreadsheet for initial data migration
  • [LOW] Score difficulty/grade distribution chart on Dashboard

5. UX Polish

  • [MED] Keyboard shortcuts: E to edit, Escape to cancel, Ctrl+S to save
  • [MED] Breadcrumb navigation: Dashboard > My Scores > Score #1234
  • [MED] Unsaved changes warning when navigating away from edit mode
  • [LOW] Dark/light theme toggle
  • [LOW] Print-friendly view of score details
  • [LOW] Export score details as PDF
  • [LOW] Skeleton loading states instead of bouncing notes (reduces perceived wait)

6. Admin & Operations

  • [MED] Dashboard analytics: total scores, scores added this month, most active users
  • [MED] User activity log for administrators
  • [LOW] Backup/export all data as JSON or CSV
  • [LOW] System health monitoring endpoint
  • [LOW] Rate limiting on public endpoints to prevent abuse

7. Account & Security

  • [HIGH] Current password verification before password change
  • [MED] Email verification on registration and email change
  • [MED] Password reset via email (forgot password flow)
  • [MED] Account deactivation (soft disable, admin can reactivate)
  • [LOW] "Last login" display on My Account page
  • [LOW] "Log out all sessions" button
  • [LOW] Two-factor authentication (TOTP)

8. Performance & Infrastructure

  • [MED] Pagination on the backend for score lists (currently loads all into memory)
  • [MED] Add nginx reverse proxy rules for API in production (currently missing from nginx.conf)
  • [LOW] Service worker for offline access to viewed scores
  • [LOW] Image optimization pipeline for uploaded scans (thumbnails, compression)
  • [LOW] CDN for static assets in production
